# Архитектура 226 · team-subscription-tracker

## Схема

```
Браузер (React SPA: #subs, #renewals, #summary, #people)
   │  fetch /api/*, cookie st_session (HttpOnly, SameSite=Lax)
   ▼
FastAPI (uvicorn, один процесс)
   ├─ web.py      вход, сессии, роли, /api/health, /api/demo/*
   ├─ main.py     маршруты, роли ops/admin
   └─ service.py  деньги и периоды, подписки, назначения, платежи, сводка, CSV
   ▼
SQLite (WAL, foreign_keys=ON), файл /data/subscriptions.sqlite3 в томе subscriptions-data
```

## Модель данных

| Таблица | Назначение | Ключевые ограничения |
|---|---|---|
| `users`, `sessions` | учётные записи | `role IN ('ops','admin')` |
| `services` | сервис по имени | `search_key UNIQUE` (имя без регистра и «ё») |
| `subscriptions` | тариф, лимит мест, период, сумма в минимальных единицах, валюта, дата продления, якорный день, статус, версия | `seats > 0`, `price_minor >= 0`, `currency IN (RUB, USD, EUR, CNY, KZT)`, `period IN (month, quarter, year)`, `anchor_day 1..31` |
| `employees` | сотрудник и отдел | — |
| `assignments` | место: подписка, сотрудник, кто и когда назначил, кто и когда освободил | **`assignments_one_active ON (subscription_id, employee_id) WHERE released_at IS NULL`**, **триггер `assignments_seat_limit`** |
| `events` | журнал: создание и правка подписки, назначение, освобождение, продление, новый сотрудник | `kind` из списка |

Занятость не хранится: `used` — подзапрос по активным назначениям, `free = max(0, seats − used)`.

## API

| Метод и путь | Что делает |
|---|---|
| `GET /api/subscriptions?q&status=active|cancelled|all` | подписки с `used`, `free`, `days_left` |
| `POST /api/subscriptions` | 201 — новая подписка; сервис находится по имени или создаётся |
| `GET /api/subscriptions/{id}` | карточка: активные назначения, история, журнал |
| `PATCH /api/subscriptions/{id} {version, …}` | правка; 409 `version_conflict` с актуальной карточкой, 409 `seats_below_used`, 409 `has_assignments` при отмене |
| `POST /api/subscriptions/{id}/renewed {version}` | «Оплачено»: дата + период от прежней даты |
| `POST /api/subscriptions/{id}/assignments {employee_id}` | 201 — новое место; 200 — сотрудник уже на месте; 409 `seats_exhausted` «Свободных мест нет: занято N из M» с карточкой |
| `POST /api/assignments/{id}/release` | освобождение; повтор — `changed=false` |
| `GET /api/renewals?within_days=0..366` | `upcoming` (каждая дата окна, `due_on`, `projected`), `overdue`, `totals` по валютам |
| `GET /api/summary` | места всего, занято, свободно, списки полных и со свободными, платежи за 30 дней |
| `GET /api/employees`, `GET /api/employees/{id}`, `POST /api/employees` | сотрудники; повтор имени — 409 `name_taken` |
| `GET /api/subscriptions.csv` | CSV (UTF-8 с BOM, «;»), ячейки с `= + - @` экранируются |

## Назначение места

```
POST /api/subscriptions/{id}/assignments
  BEGIN IMMEDIATE
    подписка не найдена / отменена        → 404 / 409
    сотрудник уже на месте               → 200, существующее назначение (changed=false)
    used >= seats                        → 409 seats_exhausted «Свободных мест нет: занято N из M»
    INSERT assignments, событие assign
      триггер assignments_seat_limit: повторно считает места → RAISE(ABORT) → 409 seats_exhausted
      уникальный индекс assignments_one_active → повтор той же пары невозможен
  COMMIT → 201 с карточкой
```

`BEGIN IMMEDIATE` берёт блокировку записи до подсчёта, поэтому параллельные запросы на последнее место выполняются по очереди: второй видит уже занятое место. Триггер и индекс — второй рубеж на случай кода, который запишет в базу в обход сервиса.

## Деньги и даты

Суммы — целые минимальные единицы (копейки, центы). Ввод «1 290,50», «1290.5», «52 000» разбирается без float. Сумма никогда не переводится между валютами: итоги — список `{currency, amount_minor, count}`.

Дата продления — локальная дата без времени. «Сегодня» — дата в часовом поясе `TZ_OFFSET_HOURS`. Следующая дата — `add_months(дата, период, anchor_day)`: якорный день хранится отдельно, поэтому 31 января → 28 февраля → 31 марта, а не 28 марта. Платежи окна строятся от сохранённой даты шагами по периоду: месячная подписка в окне 90 дней даёт три строки.

## Решения и причины

| Решение | Причина |
|---|---|
| Проверка лимита в сервисе и триггер в базе | ТЗ требует проверку в одной транзакции с назначением. Триггер ловит запись в обход сервиса, мутационный тест это подтверждает |
| Повтор назначения того же сотрудника — 200, а не 409 | повтор после потерянного ответа не должен выглядеть ошибкой и не занимает второе место |
| Освобождение ставит `released_at`, а не удаляет | по ТЗ архивное назначение остаётся в истории |
| Каждый платёж окна отдельной строкой | одна строка на подписку занижала итог окна 90 дней втрое для месячных подписок |
| Просроченная дата не входит в итог | это забытая отметка, а не будущий платёж. Она показана отдельно с кнопкой «Оплачено» |
| Список подписок по 100, поиск с задержкой 200 мс, выбор сотрудника через фильтр | на 1005 подписках каждый символ поиска перерисовывал весь список и 2006 вариантов выбора, задержка ввода 150–290 мс |
