# Приёмка 226 · team-subscription-tracker

## Как повторить проверки

```bash
docker compose up -d --build                      # http://127.0.0.1:8226, дождаться healthy
python3 scripts/container_check.py --restart      # приёмка, 7 одновременных запросов на последнее место, повтор, освобождение, валюты, права, CSV, перезапуск

cd backend && python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest                                  # 16 тестов

cd ../frontend && npm ci
npm test                                          # 2 теста Vitest
npm run build
npm run e2e:install && npm run e2e                # 16 сквозных тестов против контейнера (+1 замер, пропускается без синтетики)
docker compose exec app python -m app.synthetic 1000 2000 && npx playwright test e2e/perf.spec.ts
npm run e2e:local                                 # те же тесты без Docker (uvicorn из backend/.venv на :8326)
```

## Окружение проверки

| Компонент | Версия |
|---|---|

| Docker / Compose | 29.10.0 / 5.7.1 |
| Образы | `python:3.12-slim`, `node:22-alpine` |
| Python (тесты на хосте) / в образе | 3.13.18 / 3.12 |
| FastAPI / Pydantic / uvicorn | 0.165.0 / 2.14.4 / 0.54.0 |
| Node.js / npm | 22.23.5 / 10.9.9 |
| React / Vite / TypeScript / Vitest / Playwright | 19.3.1 / 8.3.8 / 7.0.2 / 5.1.1 / 1.65.1 |

**Особенность окружения.** Песочница перехватывает исходящий TLS прокси с собственным корневым сертификатом, поэтому `docker compose up -d --build` здесь падает на `pip install` с `certificate verify failed`. Образ собирался так: `docker build --secret id=extra_ca,src=<ca-bundle> -t team-subscription-tracker:local . && docker compose up -d`. Это путь README для корпоративного прокси. Обычная `docker compose up -d --build` в этой песочнице не проверена.

## Раунд 1. Правила и полнота продукта

Сверка с ТЗ: сервисы, тарифы, период оплаты, места, даты продления; назначение места в карточке; сводка с платежами, загрузкой и свободными лицензиями; таблицы сервисов, подписок, сотрудников и назначений; свободные места и платежи считает API; суммы в минимальных единицах, итоги по валютам; лимит проверяется в одной транзакции с назначением; архивное назначение освобождает место и остаётся в истории; контракты `GET /subscriptions`, `POST /subscriptions/{id}/assignments`, `POST /assignments/{id}/release`, `GET /renewals?within_days=30`; ограничения вместимости и одного активного назначения; граничные случаи: конкурентный запрос на последнее место, повторное назначение, две валюты; демо: пятое место занимается, шестое нет, продление через 7 дней в платежах.

| Проверка или находка | Результат |
|---|---|
| Первый запуск: миграция с триггером падала «incomplete input» | разбор SQL в `db.py` резал тело триггера по `;`. Теперь операторы собираются через `sqlite3.complete_statement`. Исправлено и в общем каркасе серверных проектов |
| **Дефект: окно платежей считало одну дату на подписку.** В окне 90 дней месячная «Макетница» давала 1 200,00 $ вместо 3 600,00 $, «Эфир» и «Склад» тоже по одному платежу | каждая дата окна отдельной строкой: первая — сохранённая дата с кнопкой «Оплачено», следующие — «следующий период» (`projected`). Итоги считают все строки. Просроченная дата в итог не входит, но следующая за ней дата окна входит. pytest на окно 90 дней и на сдвиг после просрочки, e2e на 3 строки и 3 600,00 $ |
| Тесты ловят снятие защиты: убрал проверку `used >= seats` в сервисе | падает приёмочный тест: вместо «Свободных мест нет: занято 5 из 5» срабатывает триггер с общим текстом |
| То же: убрал и проверку в сервисе, и триггер | падают параллельный тест (два 201 на последнее место) и тест ограничений базы |
| Повтор назначения того же сотрудника при полной подписке | 200 и прежняя карточка, а не 409: повтор после потерянного ответа не выглядит ошибкой |

## Известные ограничения

- Обычная `docker compose up -d --build` без прокси в этой песочнице не проверялась.
- Нет курсов валют, уведомлений, связи с биллингом сервисов.
- Сотрудника нельзя удалить или пометить уволенным через интерфейс.
- Сквозные тесты сбрасывают демо через `/api/demo/reset`: на базе с настоящими данными их запускать нельзя.
- Демо-даты строятся от дня запуска: сквозные тесты, начатые около полуночи по Москве, могут увидеть сдвиг на день.
- Один экземпляр сервера: SQLite не рассчитан на несколько реплик.
