# 226 · Учёт подписок команды

`team-subscription-tracker` — веб-приложение с сервером. Операционный менеджер ведёт подписки команды на сервисы: тариф, число мест, сумму за период в своей валюте и дату продления. В карточке подписки он назначает места сотрудникам и освобождает их. Сервер считает свободные места как лимит минус активные назначения и проверяет лимит в той же транзакции, что и назначение, поэтому последнее место не уйдёт двоим. Раздел «Платежи» показывает продления в выбранном окне с итогами отдельно по каждой валюте, «Сводка» — загрузку мест, свободные лицензии и выгрузку CSV.

Стек: React + TypeScript + Vite (интерфейс), FastAPI + SQLite (сервер). Всё упаковано в один Docker-контейнер с одним портом.

## Первый запуск (Docker)

Требования: Docker с Compose v2.

```bash
docker compose up -d --build
```

Откройте **http://127.0.0.1:8226**. Порт опубликован только на `127.0.0.1`, поэтому приложение доступно лишь с этого компьютера. При первом старте применяются миграции и создаются демоданные. Готовность — `curl http://127.0.0.1:8226/api/health` → `{"status":"ok",…}`, контейнер становится `healthy`.

| Роль | Логин | Пароль |
|---|---|---|
| Операционный менеджер (Ольга Миронова): подписки, места, платежи, сотрудники | `ops` | `ops-demo` |
| Администратор (Пётр Захаров): то же и сброс демо | `admin` | `admin-demo` |

На экране входа есть кнопки демо-входа (только при `DEMO_MODE=1`).

Демоданные: 8 сотрудников и 4 подписки. «Макетница · Команда» — 5 мест, занято 4, 1 200,00 $ в месяц, продление через 7 дней. «Поток · Бизнес» — 10 мест, занято 6, 45 000,00 ₽ в год, через 20 дней. «Эфир · Стандарт» — 3 места, все заняты, 1 490,00 ₽ в месяц, через 3 дня. «Склад · Про» — 2 места, занято 1, 9,99 € в месяц, через 45 дней. В истории «Макетницы» одно освобождённое место. Даты продления считаются от дня запуска в часовом поясе `TZ_OFFSET_HOURS` (по умолчанию 3, МСК).

```bash
docker compose exec app python -m app.seed                   # создать, если нет (повторный запуск не дублирует)
docker compose exec app python -m app.seed --reset           # вернуть демо к исходному виду (даты заново от сегодняшнего дня)
docker compose exec app python -m app.synthetic 1000 2000    # +1000 подписок, +2000 сотрудников, ~18 700 назначений для замеров
```

Данные хранятся в томе `subscriptions-data` (`/data/subscriptions.sqlite3`) и переживают `docker compose restart` и `docker compose down` + `up`. Полный сброс — `docker compose down -v`.

Если сборка идёт через корпоративный прокси с собственным корневым сертификатом (ошибка `certificate verify failed` на `npm ci` или `pip install`), передайте сертификат необязательным секретом сборки:

```bash
docker build --secret id=extra_ca,src=/path/to/ca.pem -t team-subscription-tracker:local .
docker compose up -d
```

## Демонстрационный сценарий (по ТЗ)

1. Войдите как **Ольга Миронова**. В «Подписках» откройте «Макетница · Команда»: «4 из 5 мест, свободно 1».
2. В поле «Назначить место сотруднику» выберите «Дина Петрова · Разработка» и нажмите «Назначить место». Сообщение «Дина Петрова получает место в «Макетница». Свободно: 0», в карточке «5 из 5 мест, свободно 0», в списке у подписки метка «мест нет».
3. Выбора сотрудника больше нет, вместо него: «Свободных мест нет: занято 5 из 5. Освободите место или увеличьте число мест в тарифе.» Если шестое назначение отправить из другой, ещё не обновлённой вкладки, сервер ответит тем же отказом, и карточка покажет актуальную занятость.
4. «Платежи», окно «7 дней»: «Макетница · Команда» с пометкой «через 7 дн.» и суммой 1 200,00 $. Итоги за 30 дней разделены по валютам: 46 490,00 ₽ (2 платежа) и 1 200,00 $ (1 платёж). В окне 90 дней месячная «Макетница» платится трижды: 3 600,00 $.
5. «Освободить» у сотрудника освобождает место. Запись остаётся в «Истории мест» с тем, кто освободил, а «Журнал изменений» показывает все назначения, правки и отметки продления.

## Проверки

```bash
# Сервер: pytest (деньги и месяцы, роли, приёмка, повтор назначения, освобождение, платежи по валютам, правка, конкуренция, перезапуск)
cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest

# Интерфейс: Vitest, сборка, сквозные тесты Playwright против запущенного контейнера
cd ../frontend
npm ci
npm test
npm run build
npm run e2e:install              # один раз: Chromium
npm run e2e                      # против http://127.0.0.1:8226 (docker compose up -d)
# замер: docker compose exec app python -m app.synthetic 1000 2000 && npx playwright test e2e/perf.spec.ts

# Контейнер целиком: приёмка, 7 одновременных запросов на последнее место, повтор, освобождение, валюты, права, CSV, перезапуск
cd ..
python3 scripts/container_check.py --restart
```

Сквозные тесты и `container_check.py` сбрасывают демо через `/api/demo/reset`: этот вызов удаляет все подписки, сотрудников, назначения и журнал и создаёт демо заново. Не запускайте их на базе с настоящими данными.

## Запуск без Docker (разработка)

```bash
cd backend && . .venv/bin/activate
DEMO_MODE=1 SEED_DEMO=1 uvicorn app.main:app --port 8000 --reload     # API на :8000, база ./data/subscriptions.sqlite3
cd ../frontend && npm run dev                                           # http://localhost:5226, /api проксируется на :8000
```

Собранный интерфейс без Vite: `npm run build`, затем запуск сервера с `STATIC_DIR=../frontend/dist` → http://127.0.0.1:8000. Сквозные тесты без Docker: `npm run e2e:local` (uvicorn на :8326 с временной базой, нужен собранный `dist/`).

## Учётные записи

Демо-пользователи создаются сидом. Свои — командой (пароль спрашивается скрыто):

```bash
docker compose exec -it app python -m app.users add petrov --role ops --name "Иван Петров"
docker compose exec -it app python -m app.users add boss --role admin --name "Мария Иванова"
docker compose exec -it app python -m app.users passwd petrov
```

Сотрудники, которым назначают места, — это не учётные записи: их добавляют в разделе «Сотрудники».

## Переменные окружения

См. `.env.example`: `APP_PORT` (по умолчанию 8226), `DEMO_MODE`, `SEED_DEMO`, `COOKIE_SECURE`, `TZ_OFFSET_HOURS` (часовой пояс команды: от него считается «сегодня» для продлений и платежей, по умолчанию 3). Внутри контейнера — `DB_PATH=/data/subscriptions.sqlite3`, `STATIC_DIR=/app/static`. Секретов нет: сессии — случайные токены в базе, пароли хранятся как PBKDF2-SHA256.
